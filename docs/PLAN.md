## 1. 事業定位

- **產品**：公仔與動漫周邊的預購截止日提醒網站，繁體中文，受眾是台灣的收藏者。
- **解決的問題**：錯過預購截止日，之後只能用更高的二手價買回來。
- **核心價值**：官方截止日一頁看完、快截止的排最前面、可以收藏並回來看。
- **營收模式**：導購分潤為主，之後是電子報贊助與付費提醒。
- **營運模式**：全自動。擁有者只做需要本人身分的事（註冊帳號、付款、改 repo 設定）與決策。

## 5. 搜尋與 AI 能見度

### 5.1 換自訂網域（2026-11-19 完成）

Cloudflare 的 DNS 記錄必須維持灰色雲朵（DNS only），開 proxy 會讓 GitHub 無法更新 HTTPS 憑證。Pages 不要關閉：網域仍指向 GitHub 時關閉 Pages，有被他人接管網域的風險。

**為什麼重要**：目前網站在 `eujenz.github.io` 的子路徑下，Google 不會讀到我們的 `robots.txt` 與 sitemap 宣告；網域是自己的，才能換主機而不丟排名。

**步驟**

1. 擁有者設定 DNS（GitHub Pages 的數值需查證官方文件）：`www` 用 CNAME 指向 `eujenz.github.io`；根網域用 A 記錄指向 GitHub Pages 的四個 IP。
2. 擁有者到 Settings → Pages 填入 Custom domain，等憑證簽發後勾選 Enforce HTTPS。
3. Agent 把 `site/config.mjs` 與 workflow 裡的預設 `SITE_URL` 改成新網域。網站改為根路徑，`SITE.base` 會自動變成空字串。
4. 推送後檢查：所有內部連結、`sitemap.xml`、`robots.txt`、`llms.txt`、feed、行事曆裡的網址都是新網域。
5. 確認舊網址 `eujenz.github.io/yoyaku-radar/...` 會轉到新網域。
6. 請擁有者在 Search Console 新增新網域的資源並提交 sitemap。驗證碼可沿用或請他提供新的。
7. IndexNow 金鑰檔會跟著新網域發布，第一次部署會自動送出全站網址。

**完成條件**：新網域全站可用、舊網址會轉址、Search Console 接受新 sitemap。

## 6. 行銷：Threads（等擁有者第 5 項）

**擁有者的指示**：每天兩則，偶爾提到 Yoyaku，先以 50 位追蹤者為目標。

### 6.1 架構

發文由 GitHub Actions 執行，不依賴 Agent 的工作階段是否準時被喚醒。

| 檔案 | 用途 |
|---|---|
| `social/queue.json` | 待發貼文佇列。每則有：預定日期時段、類型、內文、是否套用即時資料 |
| `social/posted.json` | 已發紀錄：時間、貼文 ID、內文 |
| `scripts/threads_post.mjs` | 取出到期的一則，必要時套入最新資料，發文，寫回紀錄 |
| `.github/workflows/threads.yml` | 每天兩個時段執行。GitHub 排程會延遲，所以各排兩個備援時間，腳本自己判斷該時段是否已發過 |

權杖放在 repo secrets `THREADS_TOKEN` 與 `THREADS_USER_ID`，由擁有者設定。

**Threads API（以下全部需查證官方文件）**：發文分兩步，先建立貼文容器再發布；需要基本與發文兩項權限；長期權杖約 60 天到期，可在到期前更新。腳本要處理權杖更新，並在更新失敗時讓 workflow 失敗，好讓監控發現。

### 6.2 內容

每天兩則，一則偏實用、一則偏互動。大約每五則提一次 Yoyaku 並附連結，其餘不提。

| 類型 | 比例 | 說明 | 資料 |
|---|---|---|---|
| 截止提醒 | 30% | 今明兩天截止的 3 到 5 件重點商品 | 發文時套用即時資料 |
| 新開預購 | 20% | 當週新開放、話題性高的商品 | 發文時套用即時資料 |
| 收藏話題 | 25% | 收納、防塵、預算、踩雷經驗、提問 | 事先寫好 |
| 動畫話題 | 15% | 當季動畫與其周邊的關聯 | 事先寫好 |
| 再販消息 | 10% | 值得注意的再販 | 發文時套用即時資料 |

**寫作規則**

- 繁體中文、台灣用語，口吻像一個愛收藏的人，不像品牌帳號。
- 只講查得到的事實。日期與價格一律來自 `data/items.json`，不憑記憶寫。
- 不用釣魚式互動（「留言 +1」之類）、不製造不存在的急迫感、不批評廠商或其他網站。
- 不上傳官方商品圖。需要圖時貼商品頁連結，讓平台自己產生預覽。
- 不冒充任何官方帳號，簡介寫明這是非官方的整理帳號。

### 6.3 流程

1. **第一週審稿期**：Agent 每天把隔天兩則草稿給擁有者看，擁有者同意才進佇列。
2. **全自動期**：擁有者明確同意後才切換。Agent 每週日寫好下週 14 則放進佇列；即時資料類的只寫框架。
3. **每日檢查**：確認前一天兩則都有發出；讀取留言與提及，整理成三類：錯誤回報、功能建議、一般互動。前兩類有具體內容才回報擁有者。
4. **回覆留言**：只回覆事實性問題（例如某商品的截止日），用網站資料回答。其餘不回，除非擁有者另有指示。

### 6.4 目標

- 30 天：50 位追蹤者（擁有者的目標）。

## 7. 營收（等擁有者第 6 項）

### 7.1 原則

- 分潤連結一律揭露：`AFFILIATE_ACTIVE=1` 後，頁尾會顯示揭露文字，連結加上 `rel="sponsored"`。
- 官方商品頁永遠是第一個、最顯眼的按鈕。不為了分潤把使用者導向較差的選擇。
- 不顯示無法查證的價格比較。

### 7.2 階段

**階段一：第一筆收入**

- 位置已預留：`site/config.mjs` 的 `PARTNERS`，顯示在每個商品頁的「其他購買管道」。
- 擁有者取得追蹤連結後：把該店家的 `url` 函式改成產生追蹤連結，設 `AFFILIATE_ACTIVE=1`，推送，實測連結能正確帶到商品或搜尋結果。
- 申請順序（費率與門檻全部需查證）：
  1. 蝦皮分潤計畫：台灣受眾最直接。網路上說有社群好友數門檻，所以排在 Threads 之後。
  2. 可寄送台灣的日本店家聯盟計畫。
- 預期：以 1% 到 5% 的分潤率，需要數百次導購點擊才會出現第一筆。所以這個階段的重點是流量，不是多接幾家。

**階段二：擴大**

- 代購與轉運平台的推薦計畫，最符合台灣收藏者從日本購買的實際流程。
- 啟動條件（目標）：每月導購點擊超過 500 次。
- 新增一頁「怎麼從日本買」，說明官方直送、代購、轉運三種方式的差別，在合適的位置放推薦連結。

**階段三：固定讀者**

- 啟用電子報（見 8），之後才考慮贊助版位。
- 付費功能的候選：特定作品的即時提醒（LINE 或 Email）。需要後端與金流，動工前要向擁有者提出成本與預期收入。
- 啟動條件（目標）：每月訪客超過 5,000，或電子報訂閱超過 300。

### 7.3 每月營收檢視

記錄：導購點擊數、各分潤平台回報的訂單數與金額、每千次瀏覽收入。數字放進儀表板。連續兩個月沒有訂單的分潤來源，檢討位置與文案，或換掉。
